# API rules — catalog-service

## Paths
- Every endpoint lives under /api/v1 (class-level @RequestMapping)
- Plural nouns, kebab-case

## HTTP methods and statuses
- Create: POST, 201 + Location
- Updates: PUT replaces the whole resource; we don't use PATCH
- Delete: 204

## Request/response objects
- JSON is snake_case (configured globally); never override names with @JsonProperty
- DTOs are records in web.dto; never expose core (entity) classes

## Errors
- All errors go through ApiExceptionHandler and use the ApiError body
- Never build error bodies in controllers
